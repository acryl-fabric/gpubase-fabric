# CLAUDE.md

This file gives Claude (Claude Code and the `claude-review` GitHub Actions workflow) the
context it needs to maintain and review this repository. **The review criteria in section 3
apply to every automated PR review.**

## 1. Repository context

- **What**: JONATHAN GPUBASE Fabric, the open-source **Core** of an Ethernet/RoCEv2 GPU cluster
  network fabric manager. License MPL-2.0. Maintainer ACRYL Inc.
- **Why**: Korean government R&D project IITP RS-2026-25525457 (2026-04 to 2028-12). A consortium of
  5 organizations develops it: ACRYL, Yonsei Univ., SKKU, Ajou Univ., and MangoBoost.
- **Commercial Extension**: JONATHAN GPUBASE (ACRYL's commercial product) lives in a private
  GitLab and includes this repository as a Git submodule. Dependency is **one-way: Extension → Core**.
  This repository must never contain Extension code, design, or customer information.
- **Layout**: polyglot monorepo. `api/` (contracts), `fabric-manager/`, `traffic-optimization/`,
  `data-acceleration/`, `security/`, `field-test/` (layers → components), `libs/<lang>/` (shared
  libraries), `research/` (relaxed rules), `deploy/`
  (umbrella Helm chart), `hack/` (scripts and templates), `docs/` (governance, guides, deliverables).
- **Key docs**: `docs/governance/NAMING.md`, `COMPONENT_CONTRACT.md`, `CORE_EXTENSION.md`,
  `LICENSE_POLICY.md`, `CI_CD.md`.

## 2. Maintenance rules

- Use `hack/new-component.sh` for new components. Then add the component to `.github/CODEOWNERS`,
  and add it to `deploy/gpubase-fabric/Chart.yaml` if it is deployable.
- Run `make verify` (contract and headers) and `make -C <component> build test` before proposing changes.
- Do not edit `LICENSE`. Do not change identifiers fixed in `NAMING.md` without explicit approval.
- GitHub Actions must use GitHub-hosted runners only. Never add `runs-on: self-hosted`.
- Diagrams in `docs/images/*.svg` are generated by `hack/diagrams/*.py`. Edit the scripts, not the SVGs.
- Commit format: Conventional Commits with DCO sign-off (`git commit -s`).

## 3. Pull request review criteria

Review the diff against the following points. Report only real issues. For each issue, give
the file and line, why it matters, and a concrete suggestion. Write review comments in
**Korean** (keep code identifiers as-is). If the PR is clean, say so briefly.

1. **Design intent (설계 의도)**: Does the change match the PR description and the component's
   README? Is the change in the right layer and component? Does it fit `api/` contracts?
2. **Performance impact (성능 영향)**: Hot paths in control or data planes, polling intervals,
   unbounded loops or allocations, blocking calls in reconcilers, metric cardinality explosions,
   and RDMA/RoCEv2-specific concerns (PFC/ECN settings, MTU, QP counts).
3. **Operational risk (운영 리스크)**: Failure modes, retries and timeouts, safe defaults,
   destructive operations on switches or nodes (config push, reboot via gNOI), RBAC scope,
   privileged containers, rollback path, and backward compatibility of `api/` (`v1alpha1` may
   change but must be called out).
4. **Core–Extension boundary (경계 위반)**: Any reference to the commercial Extension, internal
   GitLab, customer environments, or commercial-only features (large-scale cluster operations,
   advanced policy management, integrated visualization). No `if enterprise`-style branches.
   Extension points must go through `api/` plugin SPI. **Flag every violation as blocking.**
5. **Component contract (컴포넌트 계약)**: README sections (개요 / 담당 기관 / 개발 연차 /
   계획서상 산출물명 / 상태 / 빌드·실행 / 라이선스), Makefile `build`/`test`, `tests/`. For
   deployable components, also check `Dockerfile`, `image` target, and `chart/`. Check the MPL-2.0
   header on new source files. Components must not import other components directly; shared
   code belongs in `libs/<lang>/`, and cross-component or cross-language contracts in `api/`.
6. **NAMING compliance**: image `ghcr.io/acryl-fabric/gpubase-fabric/<component>`, CRD group
   `fabric.gpubase.acryl.ai`, label prefix `gpubase.acryl.ai/`, metric prefix `gpubase_fabric_`,
   Go module `github.com/acryl-fabric/gpubase-fabric`, lowercase-hyphen component names.
7. **Secrets and internal exposure (시크릿·내부 정보)**: Tokens, keys, passwords, kubeconfigs,
   private IP addresses (10.x, 172.16–31.x, 192.168.x) or internal hostnames that describe real
   infrastructure, and customer or partner names. Placeholders like `<NFS_SERVER_IP>` and
   documentation ranges (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24) are fine.
   **Flag every real secret or internal address as blocking.**
8. **License policy**: New dependencies must be Apache-2.0, MIT, BSD, ISC or MPL-2.0. LGPL is
   allowed only with dynamic linking, and EPL needs approval. GPL, AGPL, SSPL and non-commercial
   licenses are forbidden.

Out of scope: pure style nits that formatters handle. Do not approve or request changes as a
formal review state. Leave comments only, because CODEOWNERS give the binding review.
