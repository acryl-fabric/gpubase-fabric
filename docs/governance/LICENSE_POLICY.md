# 라이선스 정책

## 1. 대표 라이선스

- 저장소 전체: **Mozilla Public License 2.0 (MPL-2.0)**. 원문은 [LICENSE](../../LICENSE)이며 수정하지 않습니다.
- MPL-2.0은 **파일 단위 copyleft**입니다. 이 저장소 파일을 수정해 배포하면 그 파일은 MPL-2.0으로 공개해야 하지만,
  별도 파일로 작성한 코드(예: Extension)는 다른 라이선스를 쓸 수 있습니다. Core–Extension 구조가 이 성질에 기대고 있습니다.
- 모든 소스 파일에는 MPL-2.0 헤더를 붙입니다([hack/boilerplate](../../hack/boilerplate/README.md)). 저작권자는 소속 기관으로 적어도 됩니다.
- 기여는 DCO(`Signed-off-by`)로 받습니다. 별도 CLA는 요구하지 않습니다.

## 2. 의존성 라이선스

| 구분 | 라이선스 | 조건 |
|---|---|---|
| **허용** | Apache-2.0, MIT, BSD-2-Clause, BSD-3-Clause, ISC, MPL-2.0 | 고지(NOTICE·LICENSE)를 유지 |
| **조건부** | LGPL-2.1 / LGPL-3.0 | **동적 링크만** 허용. 정적 링크·소스 복사 금지. PR에 사용 방식 명시 |
| **조건부** | EPL-1.0 / EPL-2.0 | 별도 모듈로 사용하고 소스를 복사하지 않음. fabric-acryl 승인 필요 |
| **금지** | GPL-2.0, GPL-3.0, AGPL-3.0, SSPL, 비상업(Non-Commercial) 조건 라이선스(CC BY-NC 등), 라이선스 불명 코드 | 반입 불가 |

- 컨테이너 베이스 이미지는 OS 패키지 라이선스가 섞이므로 distroless 또는 공식 언어 이미지를 우선 사용합니다.
- 모델 가중치와 데이터셋은 저장소에 커밋하지 않습니다. 사용 시 해당 라이선스를 README에 적습니다.
- 커널 모듈, eBPF 프로그램처럼 GPL이 사실상 강제되는 영역이 필요하면 **반입 전에** fabric-acryl과 협의합니다.

## 3. 외부 코드 복사

- 다른 프로젝트 코드를 복사할 때는 원본 라이선스 헤더를 유지하고, 해당 디렉터리에 원본 `LICENSE`를 함께 둡니다.
- 출처(URL, 커밋)를 PR 본문에 적습니다.

## 4. 점검

- PR 리뷰(LLM 1차, CODEOWNERS 2차)에서 새 의존성의 라이선스를 확인합니다.
- 연 1회 이상 SBOM을 생성해 금지 라이선스 여부를 점검합니다(2차년도 자동화 예정).
